# Локальные данные

- `recipes.json.gz`: 13 703 рецепта из пользовательского архива `russian-recipes-parser-master.zip` (страницы vkuso.ru). Источник, фото и видео сохранены в карточках. Теги рассчитаны по названию, категории источника, исходным тегам и продуктам. Это эвристика, которую можно исправить чекбоксами.
- `usda.json.gz`: 8 202 записи с хотя бы одним показателем КБЖУ из двух предоставленных JSON-выгрузок USDA FoodData Central: Foundation `2026-10-29` (424 исходные записи) и SR Legacy `2018-04` (7 793 исходные записи). Записи без всех четырёх целевых нутриентов исключены только если **ни одного** из четырёх значений нет. Исходные архивы не нужны при запуске.
- `ru_usda_aliases.json`: явные русские/английские названия → FDC ID и резервные средние массы/плотности. База USDA преимущественно англоязычная; наличие записи в ней не означает автоматического распознавания любого русского названия. Неизвестный продукт можно выбрать вручную из всех записей.

## Нутриенты

Все исходные значения — на 100 г съедобной части. Белок: nutrient ID 1003; жир: 1004; углеводы: 1005. Для энергии предпочтение 1008, затем 2048, затем 2047 (ккал); если доступны только кДж 1062, деление на 4.184. Неизвестные показатели остаются `null`, нули USDA сохраняются как реальные нули. Записи содержат FDC ID, английское описание, тип набора и меры массы USDA. Несколько локальных продуктов старого справочника (например, российский творог 5%) остаются явно приблизительными и не объявляются точным аналогом американского cottage cheese.

Ручное КБЖУ продукта имеет приоритет над USDA; ручное КБЖУ блюда на порцию — над расчётом по продуктам. Если есть все БЖУ, но нет энергии, используется оценка 4/9/4. Для USDA в карточке показывается FDC ID и описание.

## Средние массы и выход

Масса штук берётся из подходящих мер USDA, ближайших к заданному обычному размеру; при отсутствии — из явного среднего справочника. Например, яйцо 50 г, репчатая луковица USDA medium 110 г, зубчик чеснока 3 г. Массу можно заменить вручную. Плотности жидкостей/сыпучих продуктов и массы ложек берутся из известных свойств/мер USDA; российский стакан принят за 250 мл, US cup — 236.588 мл, столовая ложка — 15 мл, чайная — 5 мл. Пучок 30 г, веточка 2 г, щепотка 0.3 г — грубые допущения. Для отдельных известных упаковок есть явные средние (дрожжи 7 г, разрыхлитель 10 г, ванильный сахар 8 г, банка сгущёнки 380 г); для произвольной упаковки вес не придумывается.

Указанное автором/пользователем число порций всегда приоритетно. Иначе оценивается съедобный выход и делится на типовую массу порции: суп 350 г, гарнир 180 г, каша/овощное 250 г, салат 200 г, мясо/птица/рыба 300 г, десерт 140 г, выпечка/закуска 120 г, соус 30 г, напиток 250 г. Сухие крупы увеличивают массу примерно в 2.8 раза, макароны в 2.5; если вода/бульон уже указаны, дополнительная вода не добавляется. Для мяса применяется коэффициент выхода 0.75, для некоторых печёных изделий 0.9. Расчёт **приблизительный**: это не моделирование технологии каждого рецепта и не расчёт потерь нутриентов при готовке.

Неизвестные малые количества соли/приправ могут быть пропущены **только при оценке выхода**, с пояснением. Это не превращает неизвестное КБЖУ в ноль. Крупные неизвестные количества блокируют оценку выхода. Для заготовок/неопределённой категории без указанного выхода двух порций по умолчанию нет.

При сборке интегрированной базы диапазоны вида 2–3 превращены в помеченную оценку 2.5; для некоторых приправ «по вкусу» добавлены явно условные малые количества. Оригинальные строки и основание оценки сохранены. В числовом списке покупок неизвестные количества не суммируются и перечисляются отдельно.

## Пересборка

`tools/build_usda.py` принимает путь результата и два исходных ZIP. `tools/build_bundle.py` принимает исходный архив рецептов и ранее подготовленный совместимый ZIP из `downloads`. Алиасы редактируются явно в JSON. Для запуска и Windows-сборки эти инструменты не требуются: готовые `.gz` включены в репозиторий и `.exe`.

USDA: https://fdc.nal.usda.gov/ · https://fdc.nal.usda.gov/download-datasets/

# Семейное меню для Windows

Локальное приложение: рецепты → семейное меню на 7 дней → КБЖУ и список покупок.

## Запуск

1. Скачайте репозиторий: **Code → Download ZIP**, распакуйте архив.
2. Установите [Python 3.12 для Windows](https://www.python.org/downloads/windows/) с компонентами **Tcl/Tk** и **Python Launcher** (обычно включены).
3. Дважды нажмите **start_windows.bat**. Из терминала: `py -3 app.py`.

Для запуска из исходников сторонние библиотеки не нужны. Python 3.11+ также подходит.

### Сборка .exe

Workflow [Windows application](https://github.com/Glaciatus/NJ-cooking/actions/workflows/windows.yml) запускает тесты и собирает `.exe` на Windows при изменениях `main`. После **успешного** завершения откройте запуск → **Artifacts → NJ-Cooking-Windows**, скачайте и распакуйте архив. Для этого приложения Python на компьютере уже не потребуется. Наличие workflow само по себе не подтверждает успешную сборку; смотрите статус конкретного запуска.

Локальная сборка **на Windows**:

```bat
py -3 -m pip install -r requirements-build.txt
py -3 -m PyInstaller --noconfirm --clean --onefile --windowed --name NJ-Cooking app.py
```

Результат: `dist\NJ-Cooking.exe`. Это переносимое приложение без установщика и цифровой подписи. Linux-сборка не создаёт Windows `.exe`.

## Как пользоваться

### 1. Мои рецепты

- **+ Новый** — заполните название, исходное число порций и продукты. В таблице количества относятся ко **всему исходному рецепту**. Кнопка сохранения закреплена сверху; также работает **Ctrl+S**.
- **+ Продукт** — добавление через форму, двойной щелчок — редактирование. **Вставить список** принимает строки `Рис; 400; г`, `400 г рис` или `Рис — 400 г`. Нераспознанные строки сохраняются с пометкой «уточнить».
- **Word** — загрузка `.docx`. Несколько рецептов распознаются по стилям заголовков Word (Heading1/Heading2/Title) либо названию перед строкой «Порций: 4»/разделом «Ингредиенты». Поддерживаются разделы «Продукты», «Состав», «Приготовление». Произвольная вёрстка, таблицы без подписей и старый `.doc` требуют ручного уточнения. Неинтерпретированный текст сохраняется для проверки.
- **Из ссылки** — вставьте публичную ссылку на страницу рецепта. Поддерживаются сайты с **schema.org Recipe в JSON-LD**, включая `@graph` и несколько рецептов на странице. Сохраняются название, продукты, порции, шаги, доступное КБЖУ и адрес страницы после перенаправлений. Скрипты страницы не выполняются.
- **Примеры** — добавьте девять учебных рецептов, чтобы сразу попробовать подбор. Их состав и КБЖУ приблизительны.

Импортированные рецепты сначала имеют статус **«Уточнить»**. Откройте каждый, проверьте количества и число порций, затем нажмите **«Сохранить рецепт / подтвердить импорт»**. Ссылку можно открыть в карточке, а также из сформированного меню: фото и видео остаются на исходном сайте.

### Если нет калорий, БЖУ или порций

**Неполный рецепт можно сохранить.** Он не приводит к ошибке преобразования числа и остаётся черновиком с объяснением, что уточнить.

- Пустые поля КБЖУ на порцию рассчитываются по продуктам, если все продукты и единицы распознаны. Результат помечается **«≈ Оценка»**. Расчёт ведётся по сырому съедобному весу; потери при готовке не моделируются.
- Встроенный небольшой справочник содержит типовые продукты, а не все марки и блюда. Поиск точный по названиям/алиасам; например, «рис» означает **сухой рис**, «рис отварной» автоматически с ним не отождествляется.
- В форме продукта можно указать **собственное КБЖУ на 100 г** с упаковки. Либо в карточке рецепта указать **КБЖУ готового блюда на одну порцию**: введённые значения заменят расчёт.
- Если введены все БЖУ, но нет калорий, калории оцениваются по формуле **4×Б + 9×Ж + 4×У**.
- **Неизвестно ≠ 0**. Ноль в поле означает настоящее нулевое значение. Неизвестные данные не подменяются нулями и не участвуют в подборе как известные.
- Для граммов/килограммов вес известен точно. Для штук некоторых продуктов задан примерный вес (яйцо 50 г, банан 118 г, яблоко 182 г); подсказка показывает допущение, его можно изменить. Для мл/л требуется плотность; для нескольких жидкостей она задана. Ложки и чашки автоматически в граммы не переводятся.
- Если неизвестно число исходных порций, его нужно уточнить перед подбором и масштабированием. Программа не придумывает выход рецепта.

### 2. Семья и цели КБЖУ

Укажите число людей, число порций на человека за приём пищи, суточные КБЖУ и допуски. **Все цели — на человека в сутки**, количества продуктов — на семью. Программа пока использует одинаковые цели для всех членов семьи.

Если поля пустые, используются стартовые значения:

| Показатель | Значение |
| --- | ---: |
| Калории | 2000 ккал |
| Белки | 75 г |
| Жиры | 67 г |
| Углеводы | 275 г |
| Допуск калорий | ±200 ккал |
| Допуск каждого БЖУ | ±20% |

Это настраиваемый **общий взрослый ориентир**, не индивидуальная рекомендация для каждого человека. 2000 ккал — распространённая референсная энергетическая ценность; БЖУ приблизительно соответствуют распределению энергии 15% / 30% / 55%. У детей и людей с разными потребностями цели отличаются. При изменении калорий пересмотрите также БЖУ.

Источники для понимания ориентиров: [EFSA — dietary reference values](https://www.efsa.europa.eu/en/topics/topic/dietary-reference-values), [регламент ЕС 1169/2011, приложение XIII](https://eur-lex.europa.eu/eli/reg/2011/1169/oj). Значения в небольшом справочнике — приблизительные типовые значения для сырых продуктов, ориентированные на [USDA FoodData Central](https://fdc.nal.usda.gov/); это не полная выгрузка базы. Для точности используйте данные конкретного продукта/рецепта.

**Исключить** — продукты через запятую. **Использовать остатки** — каждый продукт из списка должен встретиться хотя бы в одном блюде недели. Проверяется часть названия без учёта регистра и ё/е; словоформы и скрытые ингредиенты программа не определяет. Количество остатков пока не учитывается.

Подбор соблюдает **все четыре** суточных предела, исключения и пожелания. При невозможном сочетании показываются ближайший найденный день и рекомендации по настройкам; ограничения не ослабляются молча. Нужны готовые рецепты для трёх приёмов пищи; категория «Любой» разрешает рецепт в любом из них. Блюда могут повторяться, но подбор штрафует повторы. На больших библиотеках поиск ограничен и может не найти существующее решение.

### 3. Меню и покупки

В меню выводятся КБЖУ блюда, сумма на день (на человека и семью), сумма на неделю, среднее на человека за сутки. Продукты выводятся **на блюдо, день и неделю**. Точные совпадения названий объединяются; кг/г и л/мл приводятся к одной единице. Масса и штуки в списке покупок остаются раздельными. Кнопка сверху сохраняет меню со ссылками и покупками в `.txt` (UTF-8).

## Данные и надёжность

На Windows: `%LOCALAPPDATA%\NJ-cooking\recipes.json`, настройки рядом в `settings.json`. При обновлении автоматически создаётся предыдущая версия `.json.bak`; запись выполняется через временный файл с последующей заменой. Перед переносом на другой компьютер скопируйте эту папку. Старые рецепты первой версии читаются автоматически; БЖУ оценивается по составу, когда это возможно.

Сетевой импорт работает в фоновом потоке с тайм-аутом и ограничением размера; интерфейс остаётся доступен. Сайты без JSON-LD Recipe, страницы за авторизацией и страницы с блокировкой автоматических запросов не поддерживаются. В такой ситуации можно создать рецепт вручную и сохранить ссылку. Доступ к сайту также может ограничивать прокси или политика сети: это отдельная причина отказа, не отсутствие рецепта.

## Проверки

```sh
python -m unittest discover -s tests -v
```

На Windows запускаются также тесты настоящих окон Tk. На Linux для них нужен работающий X11 и `DISPLAY`; без него GUI-тесты явно пропускаются. Покрыты пустые и ошибочные поля, черновики, расчёт КБЖУ и порций, ограничения недели, импорт JSON-LD/Word, редактирование, старые данные, резервная копия, отчёт и видимость основной кнопки при размере 1000×700.

В облачной Linux-среде выполнены 34 теста, включая GUI на виртуальном X11. Импорт проверен на контрольных HTML-страницах и имитации HTTP-ответа; запрос к Allrecipes отклонён сетевым прокси (403), поэтому работа с этим живым сайтом не подтверждена. Проверку Windows и сборку `.exe` выполняет отдельный workflow; смотрите его фактический результат.

# Семейное меню для Windows

Локальное приложение: встроенные рецепты → меню на неделю → КБЖУ и продукты на блюдо, день и неделю.

## Запуск

1. **Code → Download ZIP**, распакуйте **весь** репозиторий, включая папку `data`.
2. Установите [Python 3.12 для Windows](https://www.python.org/downloads/windows/) с Tcl/Tk и Python Launcher.
3. Запустите `start_windows.bat` либо `py -3 app.py` из папки проекта.

Сторонние библиотеки для обычного запуска не нужны. База из **13 703 рецептов** и справочник **8 202 записей USDA** подключены автоматически и работают без интернета. Подтверждать каждый рецепт или устанавливать старый архив из `downloads` не нужно. Имеющиеся пользовательские рецепты сохраняются.

### Windows .exe

[Actions → Windows application](https://github.com/Glaciatus/NJ-cooking/actions/workflows/windows.yml) тестирует приложение, собирает `.exe` с папкой данных и проверяет встроенные ресурсы через `--self-test`. **После успешного запуска** скачайте `NJ-Cooking-Windows` из Artifacts и распакуйте. Наличие workflow не означает, что конкретная сборка уже завершилась успешно.

Сборка на Windows вручную:

```bat
py -3 -m pip install -r requirements-build.txt
py -3 -m PyInstaller --noconfirm --clean --onefile --windowed --name NJ-Cooking --add-data "data;data" app.py
```

Результат: `dist\NJ-Cooking.exe`. Linux не создаёт Windows `.exe`. Приложение переносимое, без установщика.

## 1. Базы и рецепты

### Отдельные базы данных

Сверху выберите открытую базу. **Просмотр базы и её участие в подборе — разные настройки.** Галочка «Использовать эту БД для меню» включает/выключает её для нового подбора; отключённая база остаётся доступна для просмотра и правок, отметки сохраняются.

По умолчанию есть **большая встроенная база** и **личная**. Свои новые рецепты и импорты при просмотре большой базы попадают в личную. При открытой другой пользовательской базе добавление выполняется в неё. **«Создать БД»** создаёт новый отдельный JSON-файл; **«Подключить JSON»** подключает существующий файл рецептов в формате NJ-Cooking (JSON-массив, например `personal-recipes.json`). Произвольные SQLite/Excel/USDA-файлы напрямую не являются базой рецептов этого формата. При правках подключённого файла сохраняется его резервная копия.

Поле **«Блюд из этой БД за неделю»** задаёт точное число позиций **из 21**:

- пусто — свободное количество;
- `0` — ни одного блюда из этой базы;
- например, большая `11`, личная `10` — ровно такое распределение;
- повторы считаются отдельными позициями, а не новыми уникальными рецептами;
- если число указано для всех доступных баз, сумма должна быть 21. Для личной базы без других включённых источников оставьте пусто или задайте 21.

В столбце **«В меню»** отметьте чекбоксы конкретных рецептов: каждый из них **обязательно включается хотя бы раз**. Галочку можно переключить нажатием в ячейке или пробелом на выбранной строке. Отметки сохраняются между запусками. Отметки имеют приоритет над фильтром желаемых типов блюд, но не обходят исключённые продукты, выход, квоты и строгий контроль КБЖУ: конфликт показывает ошибку, а не молча пропускает обязательный рецепт. Более 21 уникального обязательного рецепта или 8 обязательных завтраков в семидневной неделе невозможны.

**«Только обязательные»** фильтрует список. **«Сбросить поиск»** очищает поиск/фильтр и сохраняет избранное. **«Сбросить избранное этой БД»** отдельно спрашивает подтверждение с числом снимаемых отметок; рецепты и отметки других баз не удаляются. Большой список разделён на страницы по 300 строк с кнопками перехода.

Чтобы использовать только личные рецепты: откройте большую базу → снимите её галочку участия → откройте личную → оставьте её включённой → настройте отметки и составьте меню. Подбор и повторный подбор не используют отключённые источники. Пересчёт уже сохранённой недели сохраняет её старые блюда, так как это обновление расчётов, а не новый подбор.

### Карточка рецепта

Слева библиотека и поиск по названию. Список показывает выбранную базу, поддерживает поиск и страницы по 300 рецептов. **+ Новый**, **Word** и **Из ссылки** добавляют ваши рецепты. Подтверждение каждой записи не является условием подбора.

В карточке:

- количества продуктов относятся ко **всему исходному рецепту**;
- КБЖУ вводится **на одну порцию**; пустые поля рассчитываются по составу;
- число порций автора/пользователя имеет приоритет; если пусто, показана автоматическая оценка с объяснением;
- принадлежность блюда задаётся **несколькими чекбоксами**: суп, гарнир, мясное блюдо, птица, рыба и морепродукты, салат, овощное блюдо, каша, десерт, выпечка, закуска, соус, напиток, заготовка, другое;
- встроенные теги определены по исходным категориям/тегам, названию и составу. Их можно изменить или определить заново кнопкой;
- сохранение закреплено сверху, также работает **Ctrl+S**; кнопка **«Развернуть карточку»** скрывает список и отдаёт карточке всю ширину.

Статусы библиотеки: **КБЖУ есть** — достаточно данных для строгого режима; **Неполное КБЖУ** — можно использовать в мягком режиме; **Нет выхода** — нужно уточнить число порций или данные для его оценки. Сами рецепты доступны для просмотра и редактирования независимо от статуса.

### USDA и расчёт продуктов

В форме продукта можно указать собственное КБЖУ **на 100 г** либо нажать **«Выбрать продукт из полной базы USDA»**. Поиск работает по известным русским алиасам, английскому описанию или FDC ID. Выбор сохраняется для этого ингредиента; можно сохранить русское название, даже если описание USDA английское. В подсказке видны FDC ID и источник. Учитывайте raw/cooked, жирность и разновидность: сухой рис не равен варёному.

Сначала применяются ручные данные, затем явные соответствия USDA, затем небольшой локальный справочник. Автоматического приблизительного перевода любого русского названия нет. Если соответствие не найдено, оно остаётся неизвестным; его можно выбрать вручную. Наличие продукта в англоязычной USDA само по себе не гарантирует совпадение с названием в рецепте.

Граммы/килограммы пересчитываются прямо. Для штук, ложек, стаканов и жидкостей используются меры USDA либо явно заданные средние массы и плотности. Пользователь может изменить массу единицы. Диапазоны количества в интегрированной базе представлены помеченными средними оценками, исходная запись сохранена. Все такие расчёты приблизительны. Подробнее: [данные, источники и допущения](data/README.md).

### Как оцениваются порции

Если число порций отсутствует, программа определяет категорию, переводит известные количества в съедобную массу, применяет средние коэффициенты выхода и делит на типовую массу порции. Например, для супа — 350 г, гарнира — 180 г. Учитываются впитывание воды крупами и потери массы при приготовлении; уже указанная вода не добавляется повторно.

Вместо скрытого значения «2 порции» показывается **«≈ N порций» с объяснением**. Для заготовок и неоднозначных рецептов без достаточных данных выход остаётся неизвестным. Рецепт с неизвестным выходом не включается в подбор: иначе нельзя пересчитать продукты на семью. Малые неизвестные количества приправ могут быть исключены из оценки массы с пояснением, но неизвестное КБЖУ от этого не становится нулём.

Ручное число порций отключает оценку и меняет пересчёт продуктов/автоматического КБЖУ. **Если КБЖУ блюда введено вручную на одну порцию, при изменении выхода проверьте и его:** программа сохраняет явно введённые значения, не заменяя их оценкой.

### Word и ссылки

- `.docx`: распознаются заголовки Word и разделы «Ингредиенты»/«Продукты»/«Состав», «Приготовление», строки «Порций: 4». Возможен импорт нескольких рецептов. Произвольная вёрстка и старый `.doc` требуют ручного уточнения; неинтерпретированный текст сохраняется.
- Ссылка: поддерживаются страницы с **schema.org Recipe в JSON-LD**, в том числе `@graph`, и microdata (в частности Povar.ru). Для RussianFood.com добавлен разбор HTML рецепта. Сохраняются продукты, выход, шаги, источник и доступные ссылки на фото/видео. Страницы за авторизацией или блокирующие загрузку могут не поддерживаться.
- **«HTML»**: импорт сохранённой страницы сайта без подключения к интернету. Исходная ссылка определяется из страницы; если её нет, программа предложит указать её. Поддержка Povar.ru и RussianFood.com проверена на двух предоставленных сохранённых страницах.
- Авторское КБЖУ **на 100 г** сохраняется отдельно и явно подписывается; оно не переносится в поля на порцию. Для расчёта порции используются ручные данные либо оценка по ингредиентам.
- Вставка продуктов: по строке `Рис; 400; г`, `400 г рис` или `Рис — 400 г`. Нераспознанные строки отмечаются для уточнения.

## 2. Семья, желаемые блюда и контроль КБЖУ

Укажите количество людей, порций на человека за приём пищи и цели. Три приёма пищи в день. Все цели КБЖУ — **на человека в сутки**, продукты — на всю семью.

Пустые поля используют стартовый взрослый ориентир: **2000 ккал, Б 75 г, Ж 67 г, У 275 г**, допуски ±200 ккал и ±20% каждого БЖУ. Это не индивидуальная норма; для детей и различных потребностей измените значения. При изменении калорий пересмотрите и БЖУ. Справочная основа: [EFSA](https://www.efsa.europa.eu/en/topics/topic/dietary-reference-values), [энергетический ориентир ЕС](https://eur-lex.europa.eu/eli/reg/2011/1169/oj); распределение БЖУ приблизительно 15/30/55% энергии.

**«Обязательный контроль КБЖУ»**:

- **Выключен по умолчанию:** неполное КБЖУ не мешает подбору; цели — пожелание, соблюдение не гарантируется. Неизвестные показатели так и выводятся, известная часть недели показана отдельно.
- **Включён:** требуется полное КБЖУ (введённое вручную или рассчитанное). Если КБЖУ на порцию и выход известны, неизвестные количества отдельных продуктов не блокируют рецепт: они отмечаются в покупках. При этом каждый день должен попадать в заданные пределы всех четырёх показателей. Если подходящих сочетаний нет, программа объясняет проблему, не ослабляя ограничения.

**Желаемые блюда:** отметьте разрешённые теги для автоматического подбора. Рецепты, вручную отмеченные обязательными, включаются независимо от этого фильтра. Рецепт подходит при совпадении **хотя бы с одним** отмеченным тегом; без отметок разрешены все. Это фильтр, а не обещание включить каждый тип за неделю. Учитывается также принадлежность к завтраку/обеду/ужину: некоторые узкие наборы тегов не позволяют составить все три приёма пищи, тогда нужно расширить фильтр.

**Исключить продукты** и **Использовать остатки** задаются через запятую. Каждый желаемый продукт должен встретиться хотя бы в одном блюде недели. Сопоставление — по части названия, без учёта регистра и ё/е; скрытые ингредиенты и все словоформы не определяются. Количество остатка пока не учитывается.

## 3. Итоги и покупки; 4. Меню по дням

После подбора открывается вкладка **«4. Меню»**: выберите день, затем одно из трёх блюд. В большом окне видны название базы, КБЖУ на человека, продукты на семью, полное приготовление и ссылка на источник. **«Редактировать рецепт на весь экран»** открывает развёрнутую карточку. Вкладка **«3. Итоги и покупки»** содержит общий отчёт, список покупок и кнопки пересчёта/повторного подбора.

На вкладке 4 доступны ручные изменения готовой недели:

- **«Заменить блюдо…»** — поиск рецепта в подключённых и включённых базах с предварительным просмотром.
- **«Перенести / обменять…»** — выбор дня и времени приёма пищи. Обмен меняет местами два блюда; перенос сдвигает промежуточные позиции, сохраняя все 21 блюдо.
- После применения автоматически пересчитываются КБЖУ, покупки и отчёт; неделя сохраняется. Отклонения от целей, обязательных блюд, квот и фильтров показываются предупреждениями: ручное изменение остаётся вашим выбором.
- **«Отменить изменение»** возвращает предыдущую расстановку. Доступно до 20 изменений в текущем сеансе; история очищается при новом подборе и не сохраняется после закрытия.

Для изменения данных самого рецепта:

1. Исправьте КБЖУ, исходное число порций, продукты или теги.
2. **Сохраните изменения рецепта.** Появится напоминание об устаревшем отчёте; экспорт временно отключится.
3. На вкладке 4 нажмите **«Пересчитать после правок»**, сохранив выбранный день, либо на вкладке 3 выберите действие:
   - **«Пересчитать эти блюда»** — сохраняет все 21 позицию и их порядок, обновляет КБЖУ и продукты. После ручных правок выводятся отклонения от прежних целей; они не скрываются.
   - **«Подобрать заново из этих блюд»** — повторно подбирает неделю только из уникальных рецептов текущей выборки с их новыми данными и **сохранёнными целями/тегами прежнего подбора**, но текущими включёнными базами, обязательными отметками и квотами. Блюда могут переставиться/повториться. В строгом режиме может оказаться, что новых допустимых сочетаний нет; старый отчёт при этом не подменяется новым.

Для нового подбора **из всей библиотеки** или применения новых настроек нажмите **«Составить меню» на шаге 2**. Текущая неделя и параметры сохраняются между запусками. Переименование рецепта не ломает связь с меню: используется постоянный ID. Если рецепт удалён, пересчёт сообщает об этом, а не подставляет другой.

КБЖУ в отчёте выводится **только на человека**: на блюдо, день, неделю и в среднем за сутки. Продукты — на всю семью. Разные единицы складываются: `2490 г муки + 3,6 стакана муки + 6 ст. л. пшеничной муки` — это не варианты замены. Имена и несовместимые единицы намеренно не объединяются. Также видны распределение блюд по базам, выполненные обязательные отметки и источники. Неизвестные количества перечисляются отдельно и не включаются в числовые суммы. Экспорт — `.txt`, UTF-8.

## Хранение и обновление

Данные пользователя находятся в `%LOCALAPPDATA%\NJ-cooking`:

- `personal-recipes.json` — личные рецепты, отдельный JSON-массив;
- `bundled-overrides.json` — правки/скрытые записи большой базы; её исходные рецепты остаются в `data/recipes.json.gz`;
- `databases.json` — подключённые файлы, их участие, количества и обязательные отметки;
- `settings.json` — цели и фильтры;
- `menu.json` — текущая неделя с идентификаторами базы и рецепта.

При первом запуске прежний общий `recipes.json` **читается и остаётся без изменений**, а данные распределяются по отдельным файлам. Ручные правки встроенных рецептов переходят в большую базу, собственные рецепты — в личную. Обновление одной базы не переписывает файлы остальных. Перед заменой существующего файла сохраняется `.json.bak`, запись атомарная. Одинаковые ID рецепта в разных базах не смешиваются: меню использует пару «база + рецепт».

Подключённые пользовательские JSON-файлы хранятся по выбранным путям; они не сливаются с личной базой. Для переноса копируйте пользовательскую папку **и внешние подключённые файлы**; при изменении их расположения потребуется поправить пути/подключение. Встроенные базы и справочник входят в проект/`.exe`. Старый установочный архив из `downloads` новой версии не нужен.

## Диагностика ошибок (версия 0.7.0)

В шапке есть **«Журнал ошибок…»**, а при ошибке подбора показывается путь к журналу:

```text
%LOCALAPPDATA%\NJ-cooking\logs\nj-cooking.log
```

Журнал содержит версию, Python/Tk/платформу, идентификатор запроса и seed случайного подбора, цели и допуски КБЖУ, включённые базы и квоты, обязательные блюда с их выходом и КБЖУ, число доступных рецептов и дневных сочетаний, результат целевого поиска и traceback ошибок. Время — ISO 8601 с `+03:00`. Полные тексты рецептов, содержимое баз, HTTP-заголовки и переменные окружения специально не выгружаются; названия обязательных и вручную выбранных блюд и пользовательские настройки в журнале есть. Файл локальный, автоматической отправки нет.

После ошибки закройте программу и пришлите `nj-cooking.log`; если ошибка была до ротации, дополнительно нужны соседние `.1`–`.3`. Ротация: 2 МБ на файл и три предыдущих файла. Ошибки фоновых операций, callback-ошибки Tk и проблемы запуска после инициализации журнала записываются и при запуске `.exe` без консоли.

Если случайная выборка пропустила обязательное блюдо, программа дополнительно целенаправленно проверяет пары оставшихся блюд через индексы КБЖУ. Найденные дни добавляются в недельный подбор. При доказанном конфликте сообщение показывает достижимый диапазон и требуемые значения (например, минимум калорий с кашей больше верхнего предела). Если достигнут лимит поиска, это явно сообщается: отсутствие найденного решения не объявляется доказательством невозможности. Жёсткие ограничения не отключаются молча; для включения блюд без соблюдения суточных пределов можно снять «Обязательный контроль КБЖУ» на шаге 2.

## Проверки и ограничения

```sh
python -m unittest discover -s tests -v
python app.py --self-test
```

GUI-тесты требуют Windows или работающий X11 (`DISPLAY`) на Linux. Проверяются официальные данные, интеграция базы и миграция старых файлов, ручные приоритеты, автоматический выход и отсутствие двойного учёта воды, теги, строгий/мягкий режим, пересчёт текущих 21 позиций, повторный подбор из выборки, реальные окна и сохранение. Дополнительно проверяются раздельная миграция баз, выключение источника, сохранение избранного, точные количества по базам, включение всех 21 обязательных рецептов, конфликты ограничений и просмотр меню по дням.

Теги, средние веса, выход и КБЖУ — оценки, а не проверка технологии каждого рецепта. Поддерживаются не все русские названия; справочник алиасов можно расширять и выбирать USDA вручную. Не все 13 703 рецепта сразу подходят для подбора: при неизвестном выходе и крупных неизвестных количествах нужны правки. На больших библиотеках поиск сочетаний ограничен и может не найти существующее решение. Некоторые блюда повторяются; штраф за повтор уменьшает их число, но не запрещает.

Windows-сборка и проверка `.exe` вынесены в Actions; статус конкретной сборки смотрите там. Проверка живого сайта Allrecipes в облаке ранее была отклонена сетевым прокси (403); поддержка JSON-LD подтверждается контрольными страницами. Разбор Povar.ru и RussianFood.com проверен на предоставленных сохранённых страницах; живую загрузку этих сайтов облачный прокси также блокирует (403), поэтому она здесь не подтверждена. Изменение вёрстки сайта может потребовать обновления импортера.
